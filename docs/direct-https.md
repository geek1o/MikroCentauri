# Direct HTTPS on x86 and CHR

RouterOS App `use-https=yes` enables MikroTik's Cloud-dependent application URL.
It is separate from MikroCentauri's TLS listener. Cloud services are unavailable
on x86, so leave that App option disabled. The application itself still serves
HTTPS with its generated local certificate on container port 8443.

For an existing App:

```routeros
/app/set [find where name="mikrocentauri"] use-https=no
```

Use a package with `MC_DIRECT_HTTPS=1` and `MC_DIRECT_ACCESS_PORT=8443` in its
manifest. First-start bootstrap uses the declared TCP mapping rather than
`[accessPort]`, which belongs to the optional RouterOS web URL. It selects the
private literal `[accessIP]`; if no such address is available it selects the
private container IP. Public access IPs are rejected. The successful startup log
prints the exact management URL. The initial self-signed certificate must be
verified through an independent management path before trusting it.

Open `https://<private-access-IP>:8443/`, using the actual address from the startup
log. An HTTP link generated by RouterOS is not the application URL. The App's
`api-secure` mapping forwards TCP directly; it does not need a Cloud hostname or
Cloud reverse proxy. If changing the outside TCP port, change
`MC_DIRECT_ACCESS_PORT` to that same port; the internal listener remains 8443.

The image also defaults to direct HTTPS at the published port 8443 for older
App manifests, so a standard existing installation can update its image without
adding the new environment variables. Custom port mappings must specify the
correct `MC_DIRECT_ACCESS_PORT`.
Keep the persistent state volume. Do not run App cleanup or remove state to apply
this update. Existing protected settings and authentication take precedence over
all first-start environment values. A bootstrap rejection before any file write
can be retried after correcting the manifest; partially initialized state requires
individual inspection rather than automatic reset.

Set `MC_DIRECT_HTTPS=0` only for an explicitly reviewed legacy web-origin
bootstrap that supplies `MC_ACCESS_IP` and `MC_ACCESS_PORT`. Native routing remains a separate reviewed setup; successful
management startup does not activate forwarding.

References: [RouterOS Apps](https://manual.mikrotik.com/docs/containers/apps/),
[IP Cloud](https://help.mikrotik.com/docs/spaces/ROS/pages/97779929/Cloud).
