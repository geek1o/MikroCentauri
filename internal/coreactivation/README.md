# Supervised finite core activation

`New` creates an adapter for one **committed, unchanged namespace snapshot**.
It requires the locked namespace reader, immutable alias ledger, real engine
allocator and a forwarding `Barrier`. The adapter does not commit namespace
changes or replace the existing namespace activation controller. A pending or
changed snapshot denies configuration admission and readiness. All callers must
serialize namespace ownership with this lifecycle.

`Register(model)` validates and persists the source model privately, then returns
exact generated bytes for `Supervisor.Apply`. The registry is addressed by that
candidate's SHA-256; resolving a candidate regenerates its full policy and
requires strict equality. Credentials stay in 0600 files beneath a locked 0700
registry. The supervisor and registry use different private directories. Cache
mapping is trusted runtime input and points to `engine-cache.db` inside the
registry. Registry lookup survives reopen and LKG rollback.

Pass `Semantic` and `Hooks()` to the supervisor. Hooks implement:

1. Hold/cancel DNS, revoke admission and prove forwarding quarantine.
2. Resolve the registered model, check cache prerequisites, install a held gate.
3. After child start, check private nonempty cache metadata, verify ingress and
   selected path, and admit every Known alias against the ledger/backend.
4. After the supervisor commits its revision, recheck namespace, cache, path and
   fresh backend publication receipts; release forwarding and then DNS.

The caller must start sing-box with **umask0077**. The adapter never creates,
repairs, chmods, reads or rewrites its cache database. Wrong metadata fails
readiness. A missing cache after any alias reservation fails before allocator
access. First startup waits for engine-created cache metadata and the barrier's
readiness proof. Actual alias/database identity comes from admission, not file
existence. Raw dependency errors are not returned as diagnostic text.

`Check` revalidates namespace, cache, aliases and fresh backend receipts. Failure
holds DNS, revokes admission and attempts forwarding quarantine with a fresh
bounded context. Lifecycle operations are serialized so a stale checker cannot
quarantine a newly released generation. This is observation-based protection;
it cannot promise safety against unobserved in-process cache corruption between
checks or atomic packet delivery after a completed DNS response.

`NewManaged` composes this adapter, supervisor and fallback controller. Its
`Probe` callback can call `grouphealth.Prober.Probe` with a controlled canary.
Startup holds traffic; a fresh `Tick` selects a healthy endpoint, registers the
replacement and applies it through the complete supervisor sequence. Every tick
also checks the backend even when the selected endpoint is unchanged. No healthy
member or a failed runtime proof stops the child and leaves traffic held.
`UpdateModel` stages a validated model in memory after quarantine; it cannot
release an unobserved replacement. `Close` cancels observation work before
closing the supervisor and registry. `Status.Ready` requires process, group,
traffic gate and admission readiness together.

Model registrations are limited to64. `Managed.Tick` prunes unretained model
records using `Supervisor.RetainedRevisions`, including pending recovery and all
LKG revisions. Startup also prunes unused records before registration. Standalone
adapter users must serialize pruning with registration and the complete apply
operation, outside lifecycle hooks. Pruning never touches the engine cache,
namespace journal or alias ledger.

The included composition tests use a deterministic child and injected engine,
ledger and forwarding dependencies. They prove ordering, quarantine, recovery,
stale aliases, cache loss and failure boundaries; they do **not** prove native
RouterOS/TUN behavior. A concrete platform `Barrier`, startup wrapper with
private umask, coordinated namespace transitions and CHR acceptance remain
required before transparent activation is exposed through a CLI/API.
